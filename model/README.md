# Module 5 & 6 — Model Development and Deployment

Fraud-detection model training (Module 5) and real-time deployment
(Module 6) for the Business Analytics group project.

## Files

| File | Module | Purpose |
|------|--------|---------|
| `data_prep.py` | 4–5 | Shared feature engineering used by **both** training and serving (prevents train/serve skew) |
| `train.py` | 5 | Trains & compares Logistic Regression, Random Forest, XGBoost; imbalanced-data metrics + cost-based threshold; saves artifacts |
| `api.py` | 6 | FastAPI service scoring transactions in real time (`/score`, `/score_batch`) |
| `streamlit_app.py` | 6 | Fraud-analyst review-queue demo — **calls the API over HTTP** (does not load the model itself) |
| `requirements.txt` | 5–6 | Dependencies |

## Setup

```bash
cd model
python -m venv venv && source venv/Scripts/activate   # Windows Git Bash
pip install -r requirements.txt
```

## Module 5 — train

```bash
python train.py --data "D:/study/online_fraud_detection.csv"
```

- Uses a stratified sample (`--max-rows`, default 600k) for speed; pass
  `--max-rows 0` to train on the full dataset.
- Handles class imbalance via `class_weight="balanced"` (LR/RF) and
  `scale_pos_weight` (XGBoost).
- Evaluation metrics: **AUC-PR** (headline for imbalanced data), ROC-AUC,
  precision, recall, F1.
- **Operating threshold** is chosen to minimise a business cost:
  `missed-fraud loss (transaction amount) + $5 per false alarm`.
  Adjust `FALSE_POSITIVE_COST` in `train.py` and justify it in the report.
- Writes to `artifacts/`: `model.joblib`, `model_meta.json`,
  `model_comparison.csv`, and `training_reference_sample.csv` (for the
  Module 7 drift baseline).

## Module 6 — deploy

The Streamlit demo is a **client of the API** — start the API first, then
the UI. Architecture: `Streamlit UI → HTTP → FastAPI /score_batch → model`.

**1. API** (real-time scoring service):

```bash
uvicorn api:app --reload
# open http://127.0.0.1:8000/docs   (interactive Swagger UI)
```

Endpoints: `GET /health`, `POST /score` (one transaction),
`POST /score_batch` (a list of transactions).

**2. Review-queue demo** (in a second terminal, from the `model/` folder):

```bash
streamlit run streamlit_app.py
```

Point it at a remote API by setting `API_URL`, e.g.
`API_URL=https://your-api.onrender.com streamlit run streamlit_app.py`,
or edit the "API URL" box in the sidebar.

### Deploy to a cloud free tier

- **API (Render / Hugging Face Spaces):** start command
  `uvicorn api:app --host 0.0.0.0 --port $PORT`. Include the `artifacts/`
  folder in the image (commit it or run `train.py` in the build step).
- **Streamlit (Community Cloud):** point it at `model/streamlit_app.py`.

## Notes

- `artifacts/` is git-ignored — regenerate it by running `train.py`.
- The feature list is defined once in `data_prep.FEATURE_COLUMNS`; the API
  and Streamlit app import the exact same transform.

# Module 7 — Monitoring with Evidently

## 1. Objective

Module 7 monitors whether the deployed fraud detection model is still receiving data similar to the training data.

The monitoring pipeline focuses on three areas:

| Monitoring Area | Description | Requires Actual Label? |
|---|---|---|
| Data drift | Detects whether current input features differ from the training baseline | No |
| Prediction drift | Tracks changes in fraud probability and review/block rate | No |
| Model performance | Tracks precision, recall, F1-score, and confusion matrix | Yes |

In a real fraud detection system, actual labels usually arrive later through chargeback reports, manual review, or confirmed fraud cases. Therefore:

- Data drift monitoring can run immediately after deployment.
- Model performance monitoring can only run when delayed labels are available.

---

## 2. Monitoring Data Sources

Module 7 compares two datasets:

| Dataset | File | Description |
|---|---|---|
| Reference data | `artifacts/training_reference_sample.csv` | Baseline feature distribution from training |
| Current data | `artifacts/scoring_log.csv` | Transactions scored by the deployed API |

The reference data is created by `train.py`.

The current scoring log is created automatically when the API receives requests through `/score` or `/score_batch`.

## 7. How to Interpret `monitoring_summary.json`

Example:

```json
{
  "reference_rows": 5000,
  "current_rows": 200,
  "reference_avg_fraud_probability": 0.012,
  "current_avg_fraud_probability": 0.041,
  "reference_p95_fraud_probability": 0.08,
  "current_p95_fraud_probability": 0.32,
  "reference_review_rate_pct": 1.5,
  "current_review_rate_pct": 6.0,
  "data_drift_report_path": "reports/data_drift_report.html"
}
```

Meaning:

| Field | Description |
|---|---|
| `reference_rows` | Number of baseline training samples |
| `current_rows` | Number of scored transactions |
| `reference_avg_fraud_probability` | Average fraud probability on reference data |
| `current_avg_fraud_probability` | Average fraud probability on current data |
| `reference_p95_fraud_probability` | 95th percentile fraud probability on reference data |
| `current_p95_fraud_probability` | 95th percentile fraud probability on current data |
| `reference_review_rate_pct` | Percentage of reference rows predicted as review/block |
| `current_review_rate_pct` | Percentage of current rows predicted as review/block |

If `current_rows` is too small, for example below 50 rows, the monitoring result should be treated as a demo signal rather than a reliable production signal.

## 8. Important Features to Monitor

The most important features for drift monitoring are:

| Feature Group | Features |
|---|---|
| Amount features | `amount`, `log_amount`, `amount_to_oldOrg_ratio` |
| Balance behavior | `errorBalanceOrig`, `errorBalanceDest`, `orig_balance_delta`, `dest_balance_delta` |
| Time feature | `hour_of_day` |
| Transaction type | `type_CASH_IN`, `type_CASH_OUT`, `type_DEBIT`, `type_PAYMENT`, `type_TRANSFER` |
| Prediction behavior | `fraud_probability`, `prediction`, review/block rate |

Strong drift in these fields may indicate that the model is scoring transactions that differ significantly from the training distribution.

- Recall
- F1-score
- Confusion matrix
- Classification quality on delayed labels

If actual labels are not available, this step is skipped.

## 10. Retraining and Investigation Triggers

Suggested triggers:

| Signal | Trigger | Action |
|---|---|---|
| Data drift | Evidently detects dataset drift or many feature-level drifts | Investigate input data distribution |
| Prediction drift | Review/block rate changes sharply compared with reference | Check threshold and traffic profile |
| Fraud probability drift | Average or P95 fraud probability shifts strongly | Inspect high-risk transactions |
| Performance drop | Precision or recall drops after delayed labels arrive | Retrain or recalibrate the model |
| Business cost increase | Estimated cost increases materially versus validation baseline | Revisit threshold and cost assumptions |

Suggested project-level rule:

```text
Retrain or investigate when:
- data drift is detected,
- review/block rate changes by more than 2x compared with baseline,
- delayed-label precision or recall drops below the expected threshold,
- or estimated business cost increases significantly.
```

## 11. Troubleshooting

### `Current scoring log not found`

This means `artifacts/scoring_log.csv` does not exist yet.

Start the API:

```powershell
uvicorn api:app --reload
```

Then open:

```text
http://127.0.0.1:8000/docs
```

Send transactions to `/score` or `/score_batch`.

After that, rerun:

```powershell
python monitoring.py
```

---

### `AttributeError: 'Report' object has no attribute 'save_html'`

This usually means the Evidently version does not match the code.

Use this pattern:

```python
result = report.run(
    reference_data=reference_features,
    current_data=current_features,
)

result.save_html(str(DATA_DRIFT_REPORT_PATH))
```

Do not use:

```python
report.run(
    reference_data=reference_features,
    current_data=current_features,
)

report.save_html(str(DATA_DRIFT_REPORT_PATH))
```

---

### Current data has too few rows

If `scoring_log.csv` has only a few rows, Evidently may produce unstable warnings.

For a better demo, send at least 50–100 transactions through `/score_batch`.

Check scoring log size:

```powershell
python -c "import pandas as pd; df=pd.read_csv('artifacts/scoring_log.csv'); print(df.shape)"
```
